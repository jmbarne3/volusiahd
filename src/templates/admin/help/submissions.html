Everything the public sends arrives in Submissions. Nothing they send appears on the site until you act on it.

There are three kinds, shown in the Kind column:

  • Registration — someone describing their own program, with the whole listing filled in.
  • Referral — someone pointing us at a program they don't run. Usually just a name and a way to reach them.
  • Edit — someone suggesting a change to a program that's already listed, using the "Suggest an edit" link on its page.

You can correct anything about the program before you act on it: a typo, the wrong category, a missing tag, an address. Change it and press Save first — the Approve, Apply and Reject buttons don't save the page. Who sent it can't be changed.

A registration

  1. Open it. Check the category and tags — those decide where families find it.
  2. Fix anything that's wrong, and Save.
  3. Pick one of the buttons at the top:
    • Approve — publish the program puts it on the site straight away.
    • Approve as a draft creates the program but keeps it hidden, for when you want to check something first.
    • Reject if it's spam or doesn't belong in the directory.

A registration with no one-line description is created as a draft even if you publish it, because a listing needs that line. Add one on the program and publish it from there.

Places listed without a map pin (typed in their own words rather than picked from the list) come across as they are. Look them up afterwards — see Programs.

A referral

Use Approve as a draft. That keeps a record of the program without publishing anything, and gives you the details to reach out and invite whoever runs it to register it properly.

A suggested edit

An edit opens with a Suggested changes table at the top. It lists only what the person changed, with the program's current value beside their suggestion. New words are highlighted in green, and removed words are struck through in red.

  • Apply edit — update the program copies those changes onto the program. Its web address, its published status and everything they didn't touch stay as they are, and it counts as verified today.
  • Reject if none of it is right.

Using only part of an edit

Further down, the submission shows the whole listing as they sent it. Set any field you don't want back to what the program says now, Save, and that row disappears from the table. Then apply the rest.

Warnings you might see

  • "The program has been edited since this was sent." Someone changed the program after the suggestion came in. Rows marked ⚠ were changed in both places, and applying would overwrite the newer change.
  • "Applying replaces the description…" The public form only takes plain text, so a rewritten description loses its bold, lists and links. Applying an edit that didn't touch the description keeps its formatting.

Who sent an edit is shown under Who sent it, including whether they said they run the program. An edit from the people who run it deserves more weight than one from a parent.
